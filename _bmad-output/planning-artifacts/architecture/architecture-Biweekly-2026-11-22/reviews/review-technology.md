# Technology review

The architecture uses interfaces and formats implemented by the shipped kit. The one runtime seam is dependency installation during runner imports, which can break the requirement to compare all variants under the same environment.

## Findings

- **Medium — freeze dependencies before scoring.** The shipped baseline declares `xgboost>=3.2.0` in its PEP 723 metadata. The runner may invoke `uv pip install` or the current interpreter's `pip` whenever it loads a file with extra dependencies. An environment that starts with missing packages can therefore change between candidate, control, and baseline. Resolve the common dependency set before any scored phase, capture exact versions, and run the local validation command with `COMP6_DISABLE_PIP_INSTALL=1`. The host has Python 3.13.14 with NumPy, pandas, and PyArrow available, and XGBoost is currently absent. Upstream XGBoost supports CPU operation and provides Windows wheels with a Visual C++ runtime prerequisite. [Runner](../../../../../requirements/runner.py) · [Baseline](../../../../../requirements/demo_engineered.py) · [XGBoost installation guide](https://xgboost.readthedocs.io/en/stable/install.html)
- **Low — align the local reader with the upload format.** The competition requires UTF-8 source without a BOM. The shipped loader opens the file using the interpreter's default encoding. Use UTF-8 mode in the local Windows launch to read UTF-8 source with non-ASCII text. This is an implementation note. [Runner](../../../../../requirements/runner.py) · [Competition rules](../../../../../requirements/COMPETITION.md)

## Verified commitments

- The kit README recommends Python 3.12. The spine correctly uses that minor version as a compatibility reference and records the runtime actually resolved. Python 3.12.16 is a security release distributed as source. The spine makes no claim that the installed Python interpreter or organizer scorer matches that release. [Kit README](../../../../../requirements/README.md) · [Python 3.12.16 release](https://www.python.org/downloads/release/python-31216/)
- The supplied `Predictor` defines the named `train` and `predict` signatures. The single-file boundary, PEP 723 declaration, and in-class logic reflect the published submission format. The optional local `generate_features` receives the whole panel, so keeping it unused fits the split-local estimator. [Predictor interface](../../../../../requirements/predictor.py) · [Walk-forward implementation](../../../../../requirements/walkforward.py) · [PEP 723](https://peps.python.org/pep-0723/)
- `validate_submission` returns an unrounded result dictionary. Full and gauge-fix output expose `per_period`, `n_observations`, `gauge_fixed`, and `city_novelty_deg` when available. Runner CSV formatting rounds the value. The city lookup resolves from the kit working directory. The command can verify coverage against independent kit expectations because the walk-forward implementation can skip or truncate a gauge slice. [Runner](../../../../../requirements/runner.py) · [Walk-forward implementation](../../../../../requirements/walkforward.py) · [City lookup](../../../../../requirements/city_tools.py)
